# 현업 UX 시험 절차 (데모 동결 전)

목적: 새 흐름(같은 태그 대화를 입력으로 고르기, "이번 요청에 사용" 트레이, 사용한 자료·전송 기록, 실패 복구)이 실제 사용자에게 이해되는지 확인하고, [fusion-design.md](../fusion-design.md) §6의 **미확정 정책**을 정한다. 결과가 나오면 데모를 동결하고 새 저장소 설계에 반영한다.

- 대상: 현업 2–3명 (에이전트를 실제로 쓸 담당자)
- 환경: Mock 모드 데모, 시드 데이터(가상). 설정 → "시드 데이터로 초기화" 후 시작
- 시간: 1인 30–40분
- 진행자는 과업만 읽어 주고 방법을 알려 주지 않는다. 막힌 곳·되묻는 말·잘못 누른 곳을 적는다
- 기록에는 실명·사내 정보를 적지 않는다 (참가자 A/B/C)

## 정책 확인 질문 (과업 뒤)

각 질문에 참가자의 선택과 이유를 적는다. 괄호는 현재 추천값.

1. 참조 대화를 고른 뒤 원본에 새 메시지가 생기면: 자동으로 최신을 보낸다 / **알려 주고 내가 갱신한다**(추천)
2. 태그를 떼도 이미 고른 대화·파일은: **유지하고 표시**(추천) / 자동으로 뺀다
3. 입력창에서 첨부한 파일은: 그 메시지에만 / **대화 입력으로 계속 사용**(추천, 칩에서 전환 가능)
4. 파일 전달이 실패하면: 자동으로 본문을 대신 보낸다 / **멈추고 내가 고른다**(추천)
5. 팀 의견(AI 미전송 메시지)도 참조 대화에 포함할까: 예 / **아니오**(추천)
6. 요청 크기 한도(기본 256 KB)가 업무에 비해: 작다 / 적당 / 크다
