# PRD — MES Agent Hub (새 저장소)

작성일: 2026-09-27 · 기준: 데모 `mes-assistant-platform2` master (`demo-final`) · 상태: 착수용 초안

기준 구현은 데모다. 이 문서의 요구사항은 데모에서 동작·검증된 것을 서버 기반으로 옮기는 것이 원칙이다. **[데모]** 는 데모에 구현된 것, **[신규]** 는 새 저장소에서 처음 만드는 것이다.

관련: [architecture.md](architecture.md) · [openapi.yaml](openapi.yaml) · [../architecture/data-contract.md](../architecture/data-contract.md) · [../architecture/postgres-draft.sql](../architecture/postgres-draft.sql) · [../fusion-design.md](../fusion-design.md) · [../HANDOFF.md](../HANDOFF.md)

## 1. 목적

사내 AI 에이전트(OpenWebUI assistant)를 카드로 골라 대화하고, 대화끼리 태그로 느슨하게 이어 **파일과 대화를 주고받는 업무 플랫폼**. 각 에이전트의 업무 절차(질문 흐름·작성 순서·검토)는 assistant 안에 있고, 플랫폼은 **대화창 + 자료 주고받기 + 진행 기록**만 제공한다.

성공 기준:
- 담당자가 다른 대화의 결과(파일·대화)를 **화면 이동 없이** 골라 AI에 보낼 수 있다.
- 보내기 전에 **무엇이 가는지**, 보낸 뒤에 **무엇이 갔는지** 파일을 열지 않고 확인할 수 있다.
- 데모의 브라우저 한계(PC 간 공유 불가, 키 브라우저 보관, 인증 없음)가 모두 해소된다.

## 2. 사용자와 권한

| 역할 | 누구 | 할 수 있는 것 |
|---|---|---|
| 담당자 (일반 사용자) | 에이전트를 써서 업무를 하는 직원. "담당자"는 그 에이전트를 컨트롤하는 사람이라는 뜻일 뿐 **별도 권한 등급이 아니다** — 로그인한 기본 사용자(D33) | 대화 시작·참여, 태그·자료 선택, 산출물 저장, 체크리스트·노트, 완료·재개, SR 연결 업무 진행·결과 공유 |
| System Owner (SO) | 플랫폼 운영자 (여러 명) | 담당자 권한 + **에이전트 관리(추가·수정·삭제·순서)**, SO 지정, 전역 설정(기본 모델·파일 전달 방식·요청 크기 한도·SR 접수 에이전트), 타인 SR 제목 수정 |
| 요청자 = **BO (Business Owner)** | SR을 접수하는 현업 (사용자 호칭 BO, D33) | 자기 SR 접수 대화, 명시적으로 공유된 결과만 열람. 내부 대화·자료는 볼 수 없음 |

- 역할은 **서버가 강제**한다 [신규]. 로그인은 사내 SSO(§7-4) — 단, 이번 페이즈는 SSO 미연계(HANDOFF D32, 대체 인증 A1 결정 대기).
- SO 지정은 관리 화면에서 SO만 한다 [신규]. 최초 SO는 배포 설정(환경 변수)으로 지정한다.
- 대화 참여 범위: 같은 부서·팀 구분은 이번 범위에서 두지 않는다(모든 담당자가 모든 대화를 볼 수 있음). 필요 시 후속 과제.

## 3. 화면과 주요 흐름

| 화면 | 경로(데모 기준) | 요구 |
|---|---|---|
| 허브 | `/`, `?view=kanban` | 에이전트 카드(공통 순서, SO 편집 모드) ↔ 전체 대화 칸반(열=에이전트, 필터 URL 공유) [데모] |
| 새 대화 | `/new/:assistantId` | 첫 전송·첨부 때만 대화 생성, 태그 미리 채우기(`?tag=`), 참조 대화 미리 선택(`?ref=`) [데모] |
| 대화 | `/c/:taskId` | 채팅 + 오른쪽 [자료·체크·노트·이력], 좁은 화면은 탭 [데모] |
| SR 접수 | `/sr` | 요청자가 접수 에이전트와 대화 → "접수로 전환"(AI 제목) → 공유된 결과 확인 [데모] |
| SR 관리 | `/sr/manage` | 진행 현황, 연결 업무 시작(이어가기/새 대화), 결과 공유(파일 포함) [데모] |
| 에이전트 관리 | `/assistants/manage` | 전 항목 편집, 모델 ID 매핑, 체크리스트 기본값 — **SO만** [데모 + 권한 신규] |
| 리포트 | `/reports` | 완료 추이, 자료 흐름, 태그별 대화, 비효율 신호 [데모] |
| 설정 | `/settings` | 전역 설정(SO), 개인 설정(화면) [데모 → 서버 이관] |
| 로그인 | `/login` → SSO | [신규] |

대표 흐름: 카드 → 새 대화 → 전송 → 답변 "산출물로 저장" → 같은 태그 다른 대화에서 파일 또는 대화 자체를 ☑/★ → 트레이 확인 → 전송 → 답변 아래 "사용한 자료" → 완료(리포트) → SR 결과 공유.

## 4. 기능 요구사항

### 4.1 대화·태그
- FR-01 대화 1개 = 업무 1개 = 스레드 1개. 상태: 대기·진행·보류·완료, 완료 시 리포트 저장, 재개는 사유 필수 [데모]
- FR-02 태그: SR 코드(`SR-YYYY-NNNN`)·자유 키워드, 정규화(대소문자·공백·`#`), 자동완성 [데모]. 업무 코드는 서버가 고유하게 발급 [신규]
- FR-03 제목: 기본 → 첫 답변 뒤 AI 제목(별도 요청), 사람이 고친 제목은 덮어쓰지 않음 [데모]
- FR-04 여러 사람이 한 대화에 참여, 발화자 이름을 assistant에 전달, 팀 의견(AI 미전송) [데모]. 다른 PC 간 실시간 반영 [신규]

### 4.2 자료 (파일)
- FR-10 업로드는 보관이며 자동 전송이 아니다. 입력창 첨부는 기본으로 대화 입력(☑)에 고정, 칩에서 "이번 메시지만" [데모]
- FR-11 파일 버전: 같은 대화·같은 이름 저장 → 새 버전, 이전 버전 보존, 선택은 버전 고정, 새 버전은 안내만 [데모]
- FR-12 공유 자료함: 같은 태그를 **직접** 공유하는 대화의 파일, 이름 검색 [데모]
- FR-13 산출물 저장: 답변을 마크다운 산출물로, 기본 이름은 최근 산출물 이름(버전 이어짐) [데모]
- FR-14 파일은 파일 그대로 디스크·NAS에 보관, DB에는 메타데이터만 [신규, data-contract §4]
- FR-15 미리보기(텍스트·이미지)·다운로드·버전 비교 목록 [데모]

### 4.3 참조 대화
- FR-20 같은 태그를 직접 공유하는 대화를 파일처럼 ☑/★ 선택, 후보는 최근 활동순 [데모]
- FR-21 모드: 전체 원문(기본) / 메시지 선택(범위) / 요약(누를 때만 생성, 확인·수정 후 적용) [데모]
- FR-22 선택 시점 스냅샷에 고정, 새 메시지는 "갱신" 안내, 태그 해제 후에도 선택 유지(표시) [데모]
- FR-23 재귀 수집 없음, 팀 의견·실패 응답 제외, 참조 중인 대화 삭제 금지 [데모]

### 4.4 AI 요청
- FR-30 "이번 요청에 사용" 트레이: 보낼 항목·전달 방식(첨부/본문/이름만)·요청 크기를 실제 전송과 같은 계산으로 표시 [데모 → 서버 추정 API]
- FR-31 자동 절단·자동 요약 없음. 요청 크기 한도 초과 시 전송 차단 + 줄이는 방법 안내 [데모]
- FR-32 OpenWebUI 파일 첨부: 버전 이름으로 업로드, 처리 완료 확인, 주 입력 먼저. 실패 시 요청 중단 + 다시 시도·빼고 다시·텍스트로 보내기 [데모 → **서버가 대리 호출**]
- FR-33 대화당 진행 중 요청 1건, 응답 스트리밍, 중지, 시간 제한(첫 토큰 60초/파일 360초, 토큰 사이 60초), 끊긴 요청 정리(자동 재전송 없음), 응답 중 완료 금지 [데모 → 서버 작업]
- FR-34 답변마다 사용한 자료·전달 방식·크기·모델 기록, 앱 안에서 열람, 원본 요청 JSON 다운로드(키 제외) [데모]
- FR-35 모델 결정: 대화 지정 › 에이전트 매핑 › 전역 기본 [데모]
- FR-36 플랫폼은 업무 절차 프롬프트를 넣지 않는다. system 메시지는 플랫폼 컨텍스트(대화·태그·SR·고른 입력)와 주입 방지 안내뿐 [데모]

### 4.5 체크리스트·노트·이력
- FR-40 에이전트별 체크리스트 기본값 → 새 대화에 복사, 강제 아님, AI 달성도 점검(m/n)과 "판단대로 체크" [데모]
- FR-41 노트(첨부), 활동 이력, 알림 [데모]

### 4.6 SR
- FR-50 접수 대화 → 명시적 접수(번호·태그·알림), AI 제목, 요청자·SO만 제목 수정 [데모]
- FR-51 연결 업무 시작(이어가기 우선 제안), 진행 현황, 결과 공유(텍스트 + 연결 대화 산출물), 요청자 공개 범위 서버 강제 [데모 + 강제 신규]

### 4.7 관리·설정·리포트
- FR-60 에이전트 관리 SO 전용, 공통 순서 편집은 충돌 검사 [데모 + 권한 신규]
- FR-61 전역 설정 SO 전용: 기본 모델, 파일 전달 방식, 요청 크기 한도, SR 접수 에이전트. **OpenWebUI 키는 서버 비밀 저장소** [신규]
- FR-62 리포트 [데모]. 기간 집계를 완료 이벤트 시각 기준으로 [신규 보완]

## 5. 확정 정책 (D18)

[fusion-design.md](../fusion-design.md) §6의 12개를 추천값대로 확정: 대화 선택 시점 고정 + 갱신 안내 · 태그 해제 후 유지 + 표시 · 팀 의견 제외 · 대화에도 ★(복수 허용) · 한도는 바이트 256 KiB(토큰 예산은 후속) · 요약은 스냅샷에 보관 · **파일 전달 실패 시 중단 + 항목별 선택** · 첨부는 대화 입력 고정 · 재시도는 현재 선택으로(사용자 메시지 재사용) · 원격 파일 ID는 요청 기록에 보존 · OpenWebUI 업로드는 전송 시 · 후보는 최근 활동순.

## 6. 비기능 요구사항 [제안 — 운영 전 확정]

| 항목 | 제안값 | 비고 |
|---|---|---|
| 동시 사용자 | 50명, 동시 응답 스트림 20개 | 사내 사용 규모 확인 필요 |
| 파일 크기 | 파일당 50 MB, 요청당 첨부 20개 | 설정으로 조정 |
| 파일 형식 | 제한 없음(보관). AI 본문 전달은 텍스트류, 그 외는 OpenWebUI 첨부 | 실제 OpenWebUI 파일 이해 범위는 착수 후 검증 |
| 보관 | 업무 데이터·파일·요청 기록 삭제하지 않음(소프트 삭제), 요청 원본 JSON은 1년 뒤 정리 가능 | GMP 기록 보존 기준 확인 필요 |
| 감사 | 활동 이력·요청 기록은 수정 불가(추가만), 작성자·시각 기록 | 전자 서명·Part 11 대응은 범위 밖 |
| 보안 | SSO, 서버 권한 검사, OpenWebUI 키 서버 보관, 파일 경로는 서버 생성(경로 조작 차단), 주입 방지 안내 유지 | |
| 가용성 | 업무 시간 운영, 재시작 시 진행 중 요청은 "중단"으로 정리(자동 재전송 없음) | |
| 브라우저 | 최신 Edge·Chrome, 1280px 데스크톱 + 375px 모바일 조회 | 데모와 같은 기준 |
| 응답 | 화면 조회 1초 이내(대화 1,000건·파일 10,000개 규모) | |

## 7. 범위

포함: §3–§4 전부, 서버·DB·파일 저장, SSO 로그인, 권한 강제, PC 간 실시간 반영(SSE), OpenWebUI 서버 대리 호출, 데모 데이터 이관 도구(선택).

제외(후속): 부서별 열람 범위, assistant가 생성한 파일을 산출물로 자동 수신, 토큰 기준 예산, 전자 서명, 외부 접수 시스템 연동, 모바일 앱.
