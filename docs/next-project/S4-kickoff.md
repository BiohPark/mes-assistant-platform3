# S4 착수 계획 — 태스크 분할과 결정 (S4-1~10)

> **상태: 결정 확정(2026-10-01, 사용자 "승인, 모두 추천안") — HANDOFF D41.** 착수는 S3 마감(`s3-done`) 뒤. 착수 시점에 태스크별 워커·쓰기 범위를 다시 승인받는다.

S4 = SR·체크리스트·노트·알림·리포트·설정·권한. 대응표 남은 ⬜의 대부분(약 34건)이 여기 있다.
원칙: 데모 기능 100% 수용. 아래는 데모에 없거나(서버가 되면서 새로 생긴 것) 데모 그대로 갈지 확인이 필요한 지점이다.
근거: `docs/next-project/S3-design.md` §4, 데모 소스 직접 확인.

## 태스크 분할과 순서(제안)

| 순서 | 태스크 | 내용 | 먼저 하는 이유 |
|---|---|---|---|
| 1 | s4-admin | 에이전트 관리(추가·수정·삭제·순서·이미지), 전역 설정, 코드 관리, SO·BO 지정, 계정 관리 | SR은 BO 지정과 "SR 접수 에이전트" 설정이 있어야 시험할 수 있다 |
| 2 | s4-sr | SR 접수·목록·관리·전환·결과 공유, 요청자 범위 서버 강제 | 역할별 E2E의 중심 |
| 3 | s4-task-extras | 체크리스트·AI 달성도·노트·완료 절차(리포트·피드백) | 대화 화면의 남은 패널 |
| 4 | s4-notify-reports | 알림 종·읽음 처리, 리포트 화면·집계 API | 1~3의 이벤트를 소비 |
| 5 | s4-system-assistant | 시스템 어시스턴트 서랍, 도구 3종(제안 카드) | 독립적, 마지막 |

완료 기준: 역할별 E2E(SO·담당자·BO) + 데모 E1 S2 + 대응표 S4 행 전부 ✅.

## 결정 9건 — 모두 추천안으로 확정

| # | 질문 | 선택지 | 추천 |
|---|---|---|---|
| S4-1 | 비밀번호 변경·재설정 | (a) 본인 변경(현재 비밀번호 확인) + SO가 임시 비밀번호 발급, 다음 로그인 때 변경 강제 · (b) 본인 변경만 · (c) SO 재설정만 | **(a)** 메일 없이 사내망에서 닫히는 최소 구성. 비밀번호를 잊은 사용자를 SO가 풀어 줄 수 있어야 한다 |
| S4-2 | 코드 그룹 추가 범위 | (a) 그룹은 시스템이 정의, SO는 그룹 안의 코드만 추가·이름·순서·비활성 · (b) SO가 새 그룹도 생성 | **(a)** 새 그룹은 그것을 쓰는 화면이 있어야 의미가 있다. 필요해지면 그때 그룹을 추가 |
| S4-3 | 에이전트 이미지 열람 범위 | (a) 로그인 사용자 전원(업로드는 SO만) · (b) 로그인 없이도 공개 | **(a)** 허브 카드에 보이는 이미지라 전원 열람이 맞고, 비로그인 공개는 필요 없다 |
| S4-4 | 요청자(BO)가 볼 수 있는 파일 | (a) 자기 SR에 자신이 올린 첨부 + 담당자가 "결과 공유"에 담은 파일만 · (b) 연결된 업무의 산출물 전부 | **(a)** 데모 동작. 사람이 고른 것만 넘어간다는 원칙과 같다 |
| S4-6 | 완료 리포트 형식 | (a) 데모 `buildTaskReport` 그대로(완료 시점에 서버가 생성·저장) · (b) 새 형식 설계 | **(a)** |
| S4-7 | 노트 첨부 파일 | (a) 자료함 파일을 참조(데모 그대로, 별도 종류 없음) · (b) 노트 전용 종류 신설 | **(a)** DDL 변경 없음 |
| S4-8 | 알림 발생 조건 | (a) 데모 그대로 4종: 업무 배정, SR 접수, SR 상태 변경, 결과 공유 · (b) AI 응답 완료·실패 등 추가 | **(a)** 추가는 쓰면서 필요해질 때 |
| S4-9 | 리포트 기간·집계 | (a) 데모 그대로: 기간 선택(일수), 완료 시각 기준, 리드타임 = 완료 − 시작(없으면 생성) · (b) 재정의 | **(a)** 집계만 서버 API로 |
| S4-10 | 시스템 어시스턴트의 도구 호출 | (a) 데모 그대로: live는 모델에 도구 정의 전송, mock은 규칙 기반 · (b) 규칙 기반만 | **(a)** 단, 사내 모델이 도구 호출을 지원하지 않으면 제안 카드 없이 답만 나온다(오류는 아님). 사내 확인 항목에 추가 |

이미 정해진 것: S4-5(SR 접수 스레드도 RequestService 사용 — D3-1로 확정), U1(시스템 어시스턴트 수용), U9(링크 규칙은 SO 전역 설정).

## 착수 시점에 승인받을 것
- 워커: codex-main(구현), codex-critic(리뷰, 쓰기 없음) — 태스크마다
- 쓰기 범위: `apps/api/**, apps/web/**, packages/**, e2e/**, .env.example` — 태스크마다 좁혀서 제시
- DDL 변경이 필요하면(예: 임시 비밀번호 표시 컬럼) 마이그레이션을 추가한다 — MariaDB 규칙(`db-mariadb-plan.md` §3)
