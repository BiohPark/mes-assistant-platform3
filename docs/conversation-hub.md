# MES Agent Hub — 대화 중심 개편 설계 (`feat/conversation-hub`)

이전 설계([design.md](design.md))의 **어시스턴트 보드 + 산출물 패키지** 모델을 **대화 = 업무 + 다중 태그 공유** 모델로 바꾼 개편이다.
패키지(발행/받기/발췌/흐름 스트립)는 제거하고 태그로 일원화했다.

> 2026-09-26 확장: 같은 태그 대화를 **파일처럼 입력으로 고르는** 기능(전체·메시지 선택·요약, 선택 시점 스냅샷), "이번 요청에 사용" 트레이, 요청 크기 한도(자동 절단 없음), 요청 실행기가 추가됐다. 설계는 [fusion-design.md](fusion-design.md) §5·§10, 결과는 [evaluation/context-flow.md](evaluation/context-flow.md). 아래 3장의 "선택만 전달" 원칙은 대화 입력에도 그대로 적용된다.

## 1. 사용자 피드백 → 결정

| 피드백 | 결정 |
|---|---|
| 에이전트를 누르면 바로 대화할 준비 | 카드 클릭 → `/new/:assistantId` 초안. **첫 전송/첨부 때 대화 생성**(빈 업무 방지) |
| 에이전트별 진행단계 보드는 무의미 | 전체 대화 칸반 하나. 열 = 에이전트(카드와 같은 공통 순서), 단계(Lv1/Lv2)·상태는 다중 필터 |
| 카드 목록 ↔ 칸반 전환이 눈에 띄게 | 홈 상단 세그먼트 토글, URL `?view=kanban` |
| 대화 기록 = 작업, chip/badge로 연결 | `Task` = 대화(스레드 1개 고정), `tags[]` (SR 코드 + 키워드), Obsidian식 입력·자동완성 |
| 같은 chip끼리 컨텍스트(파일) 공유, 느슨한 결합 | **발견과 사용의 분리**(3장) |
| SR 등록은 간단히 | 접수 에이전트와 대화 → 명시적 "접수로 전환", AI 제목(별도 요청), 요청자/SO 수정 |
| 기본 데이터는 `참고 카탈로그` | 이미지 순서대로 12개, 모델 ID는 비움(공통 기본), 관리 페이지에서 매핑 |

Codex 설계안 대비: 지연 생성·새 버전 비교체·태그 해제 후 입력 유지·수동 제목 보호·이어가기/새 대화·URS 분석 도우미 접수는 그대로 채택했고,
단계 필터는 고정 enum 대신 카탈로그 Lv1/Lv2에서 뽑도록 일반화했다(Record 계열 포함). 메시지 발췌는 "산출물로 저장"으로 흡수해 공유 수단을 파일 하나로 통일했다.

## 2. 도메인

- `Task`: `tags`, `inputs: {fileId, weight: 'main'|'reference', selectedAt, selectedBy}[]`(특정 버전 고정), `outputFileIds`(자동), `threadId`(1개), `titleSource: 'default'|'ai'|'manual'`, `lastActivityAt`(칸반 정렬)
- `Assistant`: `order`(공통 순서, SO만 변경), `modelId?`(비면 공통 기본), `link1?`(명시 저장), `expectedInputs/Outputs`(워크플로우 다이어그램의 자료 안내, 강제 없음), 상태 `open|developing|testing|retired`
- `ServiceRequest.titleSource`, `User.isSystemOwner`
- 활동: `tag.added/removed`, `input.selected/removed`, `assistant.reordered`, `sr.task_started`
- Dexie v3: `tasks *tags, lastActivityAt` 인덱스, `packages/packageReceipts` 삭제, `upgrade()`에서 최소 변환(`db/migrations/v3.ts`)
  - srIds → SR 코드 태그, inputFileIds → 참고 입력, 한 업무의 여러 스레드 → 스레드별 대화로 분리, `working` → `developing`
  - 카탈로그에 없는 기존 에이전트는 Lv1 `이전 데모`로 보존, 카탈로그 중 없는 것만 추가
- 백업 JSON v2. v1(패키지 모델) 백업은 가져올 때 같은 변환을 거친다.

## 3. 핵심: 발견과 사용의 분리 (`domain/tags.ts`)

```
태그 공유 ──▶ 공유 자료함에 "보임"  ──(사람이 ☑/★)──▶ task.inputs ──▶ 프롬프트
```

1. **직접 공유만**: 나와 태그가 하나 이상 겹치는 대화의 파일만 보인다. A–B, B–C가 겹쳐도 A에 C 파일은 안 보인다.
2. **정리**: 출처 에이전트(공통 순서) 그룹, 파일당 한 번, 버전 체인은 최신만 펼치고 이전 버전은 접는다(접힌 버전도 선택 가능).
3. **선택만 전달**: ☑ 참고 / ★ 주 입력. 프롬프트에는 주 입력 먼저, `[주 입력] 이름 vN — 출처: WK-… · 에이전트` 라벨로 인라인.
4. **자동 교체 없음**: 선택한 버전보다 새 버전이 생기면 "새 버전 있음 · 바꾸기"만 표시(`switchInputVersion`).
5. **태그 해제 무관**: 태그를 떼면 자료함 결과만 바뀌고 선택은 "태그 해제됨"으로 남는다.
6. **삭제 보호**: 다른 대화가 입력으로 쓰는 파일/대화는 삭제 불가.
7. SR 태그가 있으면 SR 본문과 첨부(선택 가능)가 함께 보인다. 요청자 화면에는 내부 자료를 노출하지 않는다.

## 4. 화면

- **홈 카드**: 상태 배지 4종, "기본 모델" 표시, hover(대화 / OpenWebUI / 설명). SO 편집 모드는 검색·분류 필터 중 비활성, 저장/취소, 신규 등록은 끝에 붙음.
- **칸반**: 카드 = 코드·상태·AI 제목 표시·태그(최대 3)·참여자·입력 수·기한, SR 태그가 있으면 좌측 가는 SR 색 선. 상태 변경은 카드 메뉴(완료는 대화 화면의 완료 절차). 태그 칩 클릭 = 태그 필터 추가.
- **대화**: 헤더(에이전트 → 해당 열 칸반, 상태, 제목 인라인 편집·AI 제목 배지, 태그 입력, 연결된 대화 팝오버), 채팅(모델 선택: 이 대화 › 에이전트 매핑 › 공통 기본), 자료 패널(기대 자료 안내 → AI 입력 → 공유 자료함 → SR 첨부 → 이 대화 파일).
- **SR 상세**: 제목 수정(요청자/SO), 진행 현황(같은 SR 태그 대화를 에이전트 순서로), 연결 업무 시작(이어가기/새 대화), 결과 공유.
- **관리**: 모델 ID 인라인 매핑(서버 모델 목록 자동완성), 링크1 명시 입력.
